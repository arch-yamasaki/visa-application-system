# 統一アンカー実装後の精度・QAレポート - 2026-09-02

## 結論

PDF、Excel、Wordを同じ `source_locations` 契約で扱う統一アンカー実装は、**人が最終確認する運用を前提に統合可能**と判断する。

- 同じ8 fixtureを3回抽出した値精度は **88.9%〜89.5%**、合計では **769/861 = 89.3%**。
- 文書由来フィールドは、3 run合計 **1,149/1,149 = 100%** が画面表示可能なanchorへ解決された。
- semantic spotcheckは **27/28 = 96.4%**。ExcelとWordは全件一致し、PDFの1件だけ値ではなく近接ラベルを指した。
- backend、frontend、E2E、比較器、golden auditはすべて成功した。

したがって、「資料から値を取ったなら確認位置も返す」という構造上の目的は達成している。一方、表示可能なanchorが意味上も必ず正しいとは限らないため、現時点でsemantic精度100%とは扱わない。

## 値精度

| run | 一致 | 採点対象 | 正答率 | 値違い | 抽出漏れ | extra |
|---|---:|---:|---:|---:|---:|---:|
| run 1 | 255 | 287 | 88.9% | 32 | 0 | 30 |
| run 2 | 257 | 287 | 89.5% | 30 | 0 | 35 |
| run 3 | 257 | 287 | 89.5% | 30 | 0 | 28 |
| 合計 | 769 | 861 | 89.3% | 92 | 0 | 93 |

旧主指標は260/287 = 90.6%だった。今回の各runは旧指標より1.1〜1.7ポイント低く、3 run平均では1.3ポイント低い。ただし旧runの再採点ではなくGeminiを新規実行した結果なので、実装差とモデルの確率的な揺れを完全には分離できない。

抽出漏れは3 runとも0件であり、残る問題は主に値の分類・正規化・取得元の選択である。安定して多かった不一致は次の通り。

- 採用後の職種カテゴリ: 毎run 6件
- 出生地: 毎run 5〜6件
- 現在職: 毎run 4件
- 本国住所: 毎run 3件
- 国籍・地域: 毎run 2〜3件

特に職種カテゴリでは、RASENSの正式な選択肢ではなく短縮・一般化された表現を返す傾向があった。fixture固有のbackend変換を戻すのではなく、RASENSの現行選択肢を共有マスタとしてGeminiへ渡す方針が適切である。

## アンカー精度

### 構造上の表示可能率

| run | document-originフィールド | resolved / displayable | 表示可能率 |
|---|---:|---:|---:|
| run 1 | 375 | 375 | 100% |
| run 2 | 388 | 388 | 100% |
| run 3 | 386 | 386 | 100% |
| 合計 | 1,149 | 1,149 | 100% |

PDFはpageとbbox、Excelはsheetとcell、Wordはblock IDを同じ `source_locations` の中で返す。backendは参照先が原本の構造に実在することを確認し、UIが表示できるanchorへ解決する。

文書を直接根拠にしない `origin=derived` の値にはanchorを付けない。したがって、全採点項目を分母にするのではなく、文書由来フィールドを分母にした1,149/1,149が今回の設計に対応する指標である。

### 意味上の正確さ

別担当が媒体を横断して28 anchorを原本と照合した。

| 媒体 | 確認 | semantic一致 | 不一致 | 判定不能 |
|---|---:|---:|---:|---:|
| PDF | 18 | 17 | 1 | 0 |
| Excel | 5 | 5 | 0 | 0 |
| Word | 5 | 5 | 0 | 0 |
| 合計 | 28 | 27 | 1 | 0 |

PDFの不一致1件は、bbox自体は表示できるが、値ではなく近接する項目ラベル側を指していた。縦書き、画像スキャン、小さすぎるbbox、ラベルと値の近接がPDFでの主なリスクである。

この結果から、backendの構造検証だけでsemantic正確性まで保証することはできない。ただし、文字一致の複雑なfallbackを再導入する必要性も確認されていない。まずGeminiへの指示を「ラベルではなく値のquoteを含むbbox」に明確化し、人の最終確認を維持するのが最小の改善である。

## 残る課題と優先順位

1. RASENSの職種選択肢を共有マスタとして抽出時に渡し、毎run発生した職種カテゴリ6件の不一致を減らす。
2. PDF bboxがラベルではなく値を囲むよう、抽出指示とsemantic回帰サンプルを追加する。
3. 出生地、本国住所、現在職、国籍・地域について、参照資料の優先順位を明文化する。
4. response schema生成時に落ちているfield descriptionを整理する。プロンプトと重複しているなら削除し、指示を一か所に寄せる。

値精度に旧主指標からの小幅低下はあるが、アンカー統一そのものによる抽出漏れは確認されていない。今回の受け入れ条件を「文書由来の値に確認可能な位置が付き、人が最終確認できること」とするならGo、「anchorが意味上100%正しいこと」または「旧値精度90.6%以上」を必須条件にするなら追加改善後に再評価する。
